Spiel
F1 26, UDP-Format „2026". Ältere Titel senden ein anderes Format und werden nicht gelesen.
Ports
5100 Weboberfläche · 20777 Telemetrie
Programm
Eine EXE mit rund 55 MB — C++20 und Qt 6, statisch gelinkt. Kein Python, kein Chromium, keine DLLs daneben. Server und HUD laufen im selben Prozess.
Darstellung
Die QML-Szene, direkt aus der EXE. Die Renderer-Auswahl aus 0.2.x gibt es nicht mehr.
Renderer
Die QML-Szene. Die alten HTML-Seiten liegen als Rückfallebene daneben, die OBS-Schalter gelten aber nur für QML.
Renderrate
10 bis 120 Hz. Das Spiel sendet höchstens 60 Pakete/s; darüber laufen nur noch die weichen Zähler flüssiger.
Quellcode
C++20 mit Qt 6.11. packaging\build.bat baut die EXE; acht Testreihen decken alles vom Parser bis zum Updater ab. Gegen die alte Version in Python abgeglichen über je rund 20.000 Pakete aus Rennen und Quali — ohne Abweichung.
Deine Daten
Alles Persönliche liegt in data\ neben der EXE — Einstellungen, WM-Stände und Fensterlage aus 0.2.x werden unverändert weiterbenutzt. Die EXE selbst enthält keine.
Lizenzen
Der eigene Quellcode steht unter MIT. In der EXE steckt statisch gelinkt Qt 6 (LGPL-3.0); weil alles offen liegt, lässt sie sich mit einer anderen Qt-Version neu bauen.
Quellcode
Python 3.13, Flask und PySide6. run.bat legt die venv an und startet den Server, start_hud.bat das Desktop-HUD.
Deine Daten
Alles Persönliche liegt in data\ neben der EXE. Die EXE selbst enthält keine.
Mit 0.3.0 ändert sich hier einiges. Server und HUD werden ein Programm aus C++ und Qt 6 — rund 55 MB, kein Python, kein Chromium, keine Renderer-Auswahl mehr. Was das Programm meldet, steht dann im Schaltbrett unter Log. Alles zu 0.3.0

Fehlersuche

Wenn etwas klemmt.

Es kommt nichts an.

Die Statuszeile im Schaltbrett zeigt getrennt an, ob der Server läuft und ob UDP-Pakete ankommen. Sendet das Spiel ein anderes Format als 2026, kommen zwar Pakete an, werden aber nicht gelesen. Beim Testen darf außerdem nur eine Quelle auf Port 20777 senden — entweder das Spiel oder ein Testsender, sonst mischen sich die Daten.

Das HUD liegt hinter dem Spiel.

Im randlosen Vollbild schiebt sich das Spiel manchmal nach vorn. Das HUD meldet sich alle zwei Sekunden von selbst wieder oben an. Hilft das nicht, läuft das Spiel meist im echten Vollbild — fürs Bild im Stream ist ohnehin das OBS-Fenster zuständig, und das läuft davon unberührt weiter.

OBS findet das Fenster nicht.

Gesucht ist [KERS_Subsystems]: KERS OBS — nicht das HUD-Fenster. Willst du doch das HUD selbst aufnehmen, muss In OBS auffindbar im Schaltbrett an: das HUD läuft sonst als Werkzeugfenster, und genau die wirft OBS aus seiner Liste. Der Preis ist ein Eintrag in der Taskleiste — beides hängt an derselben Eigenschaft.

Ich bekomme das HUD nicht mit der Maus zu fassen.

Ab Werk ist es gesperrt — genau das lässt die Klicks zum Spiel durch. Zum Verschieben erst im Schaltbrett oder über das Symbol im Infobereich entsperren.

Das Schaltbrett meldet „Port belegt".

Auf 5100 oder 20777 läuft schon etwas — meist noch eine alte 0.2.x oder ein zweites KERS. Den UDP-Port belegt der Server allein, damit sich nicht zwei Programme die Pakete des Spiels teilen. Das andere Programm beenden, dann im Schaltbrett Start Server.

Das Handy erreicht die Regie nicht.

Beim ersten Start fragt die Windows-Firewall, ob das Programm im Netzwerk erreichbar sein darf. Wurde dort abgelehnt, in den Firewall-Einstellungen KERS_Subsystems.exe für Private Netzwerke freigeben. Am eigenen Rechner geht es auch ohne.

Wo sehe ich, was das Programm meldet?

Im Schaltbrett unter Log — dort steht, was Server und HUD melden, also das, was früher im Konsolenfenster des Servers stand. Dieselben Zeilen landen in data\kers.log; die Datei hilft auch im Discord weiter.

Das Overlay sieht anders aus als erwartet.

Beim Start aus dem Quellcode müssen die Schriften einmalig erzeugt werden: python tools\woff2_to_ttf.py. Qt kann keine woff2-Dateien lesen und fällt sonst auf die Systemschrift zurück.
