Troubleshooting

When something goes wrong.

Nothing arrives.

The status line on the control panel shows separately whether the server runs and whether UDP packets arrive. If the game sends a format other than 2026, packets do arrive but are not read. When testing, only one source may send to port 20777 — either the game or a test sender, otherwise the data mixes.

The HUD sits behind the game.

In borderless fullscreen the game sometimes pushes itself to the front. The HUD re-registers itself on top every two seconds. If that doesn't help, the game is usually in exclusive fullscreen — for the picture in the stream the OBS window is responsible anyway, and it carries on unaffected.

OBS can't find the window.

You are looking for [KERS_Subsystems]: KERS OBS — not the HUD window. If you do want to capture the HUD itself, make findable in OBS has to be on: otherwise the HUD runs as a tool window, and those are exactly what OBS drops from its list. The price is an entry in the taskbar — both hang on the same property.

I can't grab the HUD with the mouse.

It is locked by default — which is what lets clicks through to the game. To move it, unlock it first on the control panel or via the tray icon.

The overlay looks different than expected.

When starting from source the fonts have to be generated once: python tools\woff2_to_ttf.py. Qt cannot read woff2 files and otherwise falls back to the system font.

Everything else is in the project README and in the technical notes on the HUD.
