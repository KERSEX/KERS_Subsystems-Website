Game
F1 26, UDP format “2026”. Older titles send a different format and are not read.
Ports
5100 web interface · 20777 telemetry
Program
One EXE of about 56 MB — C++20 and Qt 6, statically linked. No Python, no Chromium, no DLLs alongside. Server and HUD run in the same process.
Rendering
The QML scene, straight from the EXE. The renderer choice from 0.2.x is gone.
Render rate
10 to 120 Hz. The game sends at most 60 packets/s; above that only the smooth counters run more fluidly.
Source
C++20 with Qt 6.11. packaging\build.bat builds the EXE; thirteen test suites cover everything from the parser to the updater, from access control to the OBS link. Checked against the old Python version over roughly 20,000 packets each from a race and a qualifying session — no deviation.
Access
Only this PC gets to the control page, settings and camera keys as it is. Every other device enters the 6-digit code from the control panel once; devices and IPs can be blocked, and five failed attempts mean a 60 s pause. Other websites in this PC's browser can't reach the server.
Updates
On start the program checks for a newer version. Only what GitHub delivers with a SHA-256 checksum gets installed; the old file stays behind as a fallback.
Your data
Everything personal lives in data\ next to the EXE — settings, championship standings and window position from 0.2.x carry over unchanged. The EXE itself contains none.
Licences
The project's own source is MIT. The EXE contains Qt 6 statically linked (LGPL-3.0); since everything is open, it can be rebuilt against another Qt version.

Troubleshooting

When something goes wrong.

Nothing arrives.

The status line on the control panel shows separately whether the server runs and whether UDP packets arrive. If the game sends a format other than 2026, packets do arrive but are not read. When testing, only one source may send to port 20777 — either the game or a test sender, otherwise the data mixes.

The HUD sits behind the game.

In borderless fullscreen the game sometimes pushes itself to the front. The HUD re-registers itself on top every two seconds. If that doesn't help, the game is usually in exclusive fullscreen — for the picture in the stream the OBS window is responsible anyway, and it carries on unaffected.

OBS can't find the window.

You are looking for [KERS_Subsystems]: KERS OBS — not the HUD window. If you do want to capture the HUD itself, make findable in OBS has to be on: otherwise the HUD runs as a tool window, and those are exactly what OBS drops from its list. The price is an entry in the taskbar — both hang on the same property.

I can't grab the HUD with the mouse.

It is locked by default — which is what lets clicks through to the game. To move it, unlock it first on the control panel or via the tray icon.

The control panel says “port in use”.

Something is already running on 5100 or 20777 — usually an old 0.2.x or a second KERS. The server takes the UDP port for itself, so two programs never split the game's packets between them. Close the other program, then press Start Server.

My phone can't reach the control page.

On the first start the Windows firewall asks whether the program may be reached on the network. If that was declined, allow KERS_Subsystems.exe for private networks in the firewall settings. On the PC itself it works without.

My phone shows “KERS Subsystems — Code”.

The device isn't cleared yet: enter the 6-digit code from the control panel (Access). It stays cleared after that. If it says “blocked”, clear the device again on the control panel under Devices ….

The OBS card on the control page stays “disconnected”.

Switch on the WebSocket server in OBS (Tools → WebSocket Server Settings, port 4455). If OBS asks for a password, enter it in /settings under OBS control. If OBS runs on another PC, its address goes there too.

Where do I see what the program reports?

On the control panel under Log — what server and HUD report, i.e. what used to be in the server's console window. The same lines go to data\kers.log; the file is also what helps on Discord.

Everything else is in the project README and in the technical notes on the HUD.
