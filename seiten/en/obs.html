Recording & stream

Capturing the transparent HUD itself doesn't work — which is why there is a second window.

A second window, three steps.

It freezes on a single frame in a window capture. So KERS Subsystems draws the same scene a second time: opaque, at canvas size, purely for recording.

01

Switch the window on

On the control panel under OBS, enable the dedicated OBS window and set the canvas size to whatever OBS is set to — usually 1920×1080.

The desktop HUD may stay off. The OBS window runs independently.

02

Capture it in OBS

Window capture → window [KERS_Subsystems]: KERS OBS, method “Windows 10 (1903 and up)”, capture window frame off.

03

Colour key

Put a colour key filter on the source, key colour magenta.

Not a workaround but the plan: in the OBS window every panel is opaque so the key doesn't eat into it. Magenta because the colour appears nowhere in the overlay — green clashes with sectors and DRS, blue with Alpine, Williams and RB.

What about a display capture? The HUD sits on the desktop, so a screen capture picks it up automatically. It still makes a poor stream: you get everything else on screen as well, the overlay depends on your monitor's resolution and position instead of the OBS canvas, and nothing can be shown or hidden separately any more. The dedicated OBS window is the recommended way.
Why not the HUD window itself? A transparent window draws straight into the desktop via DirectComposition on Windows. Windows Graphics Capture, which feeds the OBS window capture, reads the DWM redirection surface instead — and that stops receiving new frames for such a window. With one window it can't be solved: either transparent for the desktop or opaque for the recording. Hence two.
